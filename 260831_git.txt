시각화 설계와 스토리텔링 

1. 데이터 시각화의 이해

(1) 데이터 시각화
- 데이터를 차트나 도표로 표현하여 보는 사람이 쉽게 이해할 수 있도록 만드는 것

단순히 그래프를 예쁘게 만드는 것이 아니라
→ 데이터의 인사이트를 효과적으로 전달하는 것이 목적

좋은 시각화의 3가지 요소
- DATA : 정확하고 검증된 데이터
- DESIGN : 오해 없이 읽히는 형태
- STORY : 결론과 행동으로 이어지는 이야기

좋은 시각화 = DATA + DESIGN + STORY


(2) 탐색적 시각화 vs 설명적 시각화

[탐색적 시각화]

목적
→ 데이터에서 인사이트를 찾는 것

특징
- 분석 초기 단계
- 아직 결론이 없음
- 여러 차트를 만들어보며 탐색
- 주로 분석가 자신이나 분석팀이 사용

[설명적 시각화]

목적
→ 이미 찾은 결론을 다른 사람에게 전달

특징
- 분석 이후 사용
- 이미 결론이 있음
- 적은 수의 차트를 정확하게 구성
- 의사결정자나 외부 이해관계자에게 전달

탐색적
→ 결론을 찾기 위한 시각화

설명적
→ 결론을 전달하기 위한 시각화


(3) 정적 시각화 vs 동적 시각화

[정적 시각화]

한 번 보고 끝나는 자료
EX)
- 보고서
- PPT
- 이미지

→ 작성자가 결론을 정해서 전달

[동적 시각화]

사용자가 반복해서 데이터를 탐색하는 자료
EX)
- 대시보드
- 필터
- 드릴다운

→ 사용자가 직접 데이터를 탐색하며 결론을 발견

판단 기준 => 이 화면을 몇 번 볼 것인가?

1회성
→ 정적 시각화

반복 조회
→ 동적 시각화

2. 시각화 설계 원칙

(1) 정확한 비교가 중요하면 막대그래프

사람은 공통된 축 위에서
위치와 길이를 비교할 때 가장 정확하게 판단

따라서 정확한 값 비교가 목적이면 → 막대그래프를 우선 고려

파이 / 버블 / 3D → 정확한 값 비교에는 상대적으로 부적합

파이차트
- 항목이 약 3~5개
- 대략적인 구성비만 보여줄 때
- 정확한 순위 비교가 필요하지 않을 때 사용

(2) 불필요한 요소 제거

차트에서 데이터를 이해하는 데 필요하지 않은 장식은 제거

제거 대상
- 3D 효과
- 그림자
- 진한 그리드선
- 불필요한 테두리
- 불필요한 배경색
- 중복 범례
- 과도한 눈금

* 간결하게 만든다 ≠ 여백까지 없앤다
* 필요한 여백은 유지.

(3) 막대그래프 Y축은 0부터 시작

막대그래프는 막대의 길이가 값을 의미
=> Y축을 중간부터 시작하면 실제 차이가 과장되어 보일 수 있음.

막대그래프
→ Y축 0부터 시작

선그래프
→ 추세가 중요하기 때문에 경우에 따라 축 절단 가능

(4) 이중 Y축은 가급적 피하기

두 데이터의 축 범위를 임의로 조정하면 실제로 없는 상관관계가 있는 것처럼 보일 수 있음.

=> 대체
- 첫 시점을 100으로 지수화
- 차트를 따로 나누기


(5) 비교 기준에 주의

1. 체리피킹

특정 기간만 선택해서 보여주면 같은 데이터도 다른 결론처럼 보일 수 있음.
→ 전체 기간을 보여주고 관심 구간을 강조

2. 보정 없는 절대값

지역이나 집단의 규모가 다른데 단순 건수만 비교하면 잘못된 결론이 나올 수 있음.

EX)
지역별 범죄 건수 비교
→ 단순 건수만 비교 X
→ 인구 10만 명당 범죄 건수처럼 보정

3. 부적절한 기준

전년 데이터가 이상치라면 전년 대비 증감률만으로 판단하면 안 됨.
→ 3개년 평균 / 목표 / 업계 평균 등도 함께 고려

(6) 색은 의미가 있을 때만 사용

색은 장식이 아니라 중요한 정보를 강조하기 위해 사용.

가장 효과적인 방법
→ 회색조 + 강조색 1개

중요하지 않은 데이터
→ 회색

강조할 데이터
→ 포인트 색상

색 종류

1. 범주형
→ 서로 다른 종류 구분

2. 순차형
→ 값의 크기 표현
→ 연한색 → 진한색

3. 발산형
→ 기준값을 중심으로 증가 / 감소 표현

(7) 제목에는 결론을 작성

차트 = 근거
제목 = 결론

단순 제목보다 결론을 알려주는 제목이 좋음.

EX)
"월별 매출 추이" X
"3분기 매출, 전년 대비 18% 감소" O
이러한 제목 => Action Title

(8) 필수 정보 표시
보고용 차트에는 다음 정보를 표시하는 것이 중요
- 단위
- 기간
- 출처
- N수

특이한 시점에는 주석(Annotation)을 사용.

EX)
7월 매출 급감
→ "7월 시스템 장애"

3. 목적에 따른 차트 선택

(1) 비교
질문
→ 무엇이 더 큰가?
추천
→ 가로 막대그래프

(2) 구성
질문
→ 전체가 무엇으로 이루어져 있는가?
추천
→ 100% 누적막대
항목이 3~5개 정도라면
→ 파이차트도 가능

(3) 추세
질문
→ 시간에 따라 어떻게 변했는가?
추천
→ 선그래프

(4) 분포
질문
→ 데이터가 어떻게 퍼져 있는가?
추천
→ 히스토그램 / 박스플롯

(5) 관계
질문
→ 두 변수가 함께 움직이는가?
추천
→ 산점도

(6) 변화 기여
질문
→ 무엇 때문에 증가하거나 감소했는가?
추천
→ 워터폴

(7) 단계 이탈
질문
→ 어느 단계에서 많이 빠지는가?
추천
→ 퍼널

(8) 지리
질문
→ 어느 지역이 다른가?
추천
→ 지도 + 순위 막대

4. 주요 그래프 핵심

(1) 막대그래프
목적
→ 범주별 값 비교

- Y축은 0부터 시작
- 기본적으로 값 기준 정렬
- 항목 이름이 길면 가로 막대 사용

* 연령대 / 등급처럼 순서 자체에 의미가 있다면 원래 순서 유지

(2) 파이차트
목적
→ 전체 구성비 확인
단점
→ 정확한 값 비교가 어려움
* 항목이 너무 많으면 사용하지 않는 것이 좋음.
* 대략 3~5개 정도일 때 적합.

(3) 산점도
- 두 연속형 변수의 관계 확인
- 이상치 발견

점이 너무 많이 겹치면
→ 투명도(alpha)를 낮춰서 표현

(4) 히스토그램 vs 막대그래프

[히스토그램]
목적
→ 연속형 데이터의 분포 확인
X축
→ 연속된 구간(bin)
막대 사이
→ 붙어 있음

[막대그래프]
목적
→ 범주별 값 비교
X축
→ 범주
막대 사이
→ 떨어져 있음

5. Matplotlib 핵심

(1) 기본 그래프
plt.plot()
→ 선그래프
plt.bar()
→ 세로 막대그래프
plt.barh()
→ 가로 막대그래프
plt.scatter()
→ 산점도
plt.hist()
→ 히스토그램

(2) 그래프 기본 설정

plt.xlabel()
→ X축 이름
plt.ylabel()
→ Y축 이름
plt.xlim()
→ X축 범위
plt.ylim()
→ Y축 범위
plt.legend()
→ 범례
plt.show()
→ 그래프 출력

(3) 여러 그래프

subplot
→ 한 화면을 여러 영역으로 나누어 그래프 배치
GridSpec
→ 각 그래프의 크기를 다르게 배치
* 가장 중요한 차트를 가장 큰 영역에 배치
* 여러 차트를 비교할 때는 → 축 범위를 통일

6. 데이터 스토리텔링

(1) 데이터 스토리텔링의 목적

보고의 목적은 단순히 데이터를 보여주는 것이 아님.
→ 상대방이 의사결정을 할 수 있도록 만드는 것

(2) 스토리텔링 3막 구조

1. SETUP
현재 상태 / 공통된 사실 제시

EX)
"현재 이탈률은 12%다."

2. CONFLICT
문제나 예상과 다른 부분 제시

EX)
"그런데 이탈 고객의 절반이
가입 후 3개월 안에 이탈한다."


3. RESOLUTION
해결책 / 선택지 / 요청 제시

EX)
"온보딩을 개편하면
이탈률 4%p 개선이 예상된다."

* 현재 상태
→ 문제
→ 해결책 / 행동


7. 청중에 따른 보고 방식

(1) 경영진
- 그래서 무엇이 중요한가?
- 얼마인가?
- 언제인가?
————————————
- 결론부터
- 핵심 지표는 적게
- 금액 / 비율 / 리스크 중심
- 상세 내용은 부록

(2) 공공기관
- 근거
- 형평성
- 절차
———————
- 출처 명시
- 분석 방법 명시
- 지역 / 계층별 분석
- 지도 / 시계열 / 표 활용


(3) 실무팀
→ 어떻게 실행할 것인가?
———————————
- 데이터를 상세하게 분해
- 지표 정의 명확하게
- 세분화된 차트 활용


(4) 외부 공개
→ 쉽게 이해할 수 있는가?
————————————-
- 1차트 = 1메시지
- 전문용어 최소화
- 설명과 캡션 충분히 작성

8. 경영진 보고 핵심

(1) 첫 30초 안에 결론 제시
배경부터 길게 설명하지 않음.
→ 결론 먼저

(2) 핵심 지표는 3개 이하
중요한 지표만 본문에 표시
나머지
→ 부록

(3) 마지막에는 행동이나 요청 제시

(4) BLUF
Bottom Line Up Front
= 결론을 먼저 말하는 방식
→ 핵심 근거
→ 상세 데이터
