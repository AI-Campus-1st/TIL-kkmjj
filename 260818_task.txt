크롤링

클라이언트와 서버
- 크롤러 : 브라우저 자리에 대신 앉는 프로그램

# 브라우저가 하는 는일
요청 -> 응답 -> 렌더링 -> 화면
# 크롤러가 하는 일
요청 -> 응답 -> 파싱 -> 데이터
- 필요한 값만 꺼냄

HTTP
- 브라우저와 서버가 대화할 때 지키기로 한 형식
- HyperText Transfer Protocol = 문서를 주고 받기 위한 전송 규약
- 요청과 응답은 정해진 순서와 형식을 따름. 프로그램이 읽을 수 있음
- “요청라인 | 헤더 | 바디 “ 세 부분으로 이루어짐

요청의 구조
- 요청라인
> 매서드(get/post)와 경로가 들어감
- 헤더
> 요청에 대한 부가 정보, user-agent(어떤 프로그램인지), accept( 어떤 형식 원하는지)
- 바디 
> 서버에 보낼 내용, get은 보통 비어있고, post에서 본격적으로 쓰임

응답의 구조
- 상태줄
> 요청이 어떻게 처리 됐는지 숫자로 알려줌. 크롤러가 가장 먼저 확인 해야할 값
- 헤더
> 응답 본문의 형식(content-type), 인코딩, 쿠키, 본문을 해석하는데 필요한 정보
- 바디
> 실제 내용, html문서, json 데이터나 이미지 -> 파싱할 대상

Requests
- 파이썬으로 브라우저와 똑같은 요청을 보냄
ex)
import requests
URL = "https://finance.naver.com/ sise/sise_quant.nhn "
response = requests.get(URL)
print(response.status_code) # 200
print(response.text) # HTML 문자열

EX)

"User- Agent": "Mozilla/5.0 ...",

Params | timeout | 인코딩
EX)
params = {" sosok": 0}
response = requests.get(URL, params=params, timeout=10)
response.text 					# str — 인코딩을 추정해디코딩
response.content 					# bytes — 원본그대로
response.encoding = "utf - 8" 		# 한글이깨질때

- Params 사용 -> 주소를 문자열로 붙이지 X ㄱㄴ
- Timeout X -> 응답 없는 서버에서 영원히 멈춤
- 한글 깨짐 -> encoding 직접 지정

HTML 객체

EX)
import requests
from bs4 import BeautifulSoup
response = requests . get(URL)
soup = BeautifulSoup(response.text, "html.parser")

- response.text : 긴 문자열
- BeautifulSoup : 탐색 가능한 트리
- Html.parser : 기본 내장 / lxml은 더 빠름

Find | find_all
- 이름과 속성으로 태그를 찾음
EX)
Soup.find(“title”) 		# 가장 위에 있는거 하나 
Soup.find(“li”, class="type1”) # class로 좁히기
Soup.find(id=“content area”) # id로 찾기
Soup.find(“a”, attrs={"class”:”thumb”})
Soup.find.all(“li”) 

- class는 파이썬 예약어라 class_ 로 돌려씀
- Find 하나 | find_all은 리스트로 돌려줌
- 못찾으면 None - 바로 .text를 부르면 오류가 남

Select | select_one

EX)

soup.select('a[ href^="/item/ main.naver?code "]')

=> find, select 섞을 수 있음
